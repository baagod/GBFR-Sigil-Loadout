# 单元格选区：视觉规格与历史约束

> 现行实现是「单层 overlay」画选区与复制区，方案见 [表格选区与拖选性能方案](表格选区与拖选性能方案.md)。
> 本文只保留**像素规格与踩过的坑** —— 形状、层级、握把/末列这些语义不随实现方式变化。
> 早期「逐格挂类名 + 伪元素画边」的实现已删除，但下面的几何与不变量仍然适用于 overlay。

## 一、两条线各占哪几像素

基准 = 格子的**边框盒**；格线是**格子自己的** `border-right / border-bottom`（1px）：

| 线 | 宽 | 上 / 左 | 右 / 下 |
| --- | --- | --- | --- |
| **实线**（选区） | 3px | 格外 2px + 格内 1px | 格内 2px（贴表格末边时再收 1px） |
| **虚线**（复制区） | 2px | 格外 1px + 格内 1px | 格内 2px |

一条通用关系：`inset = 线宽 − 1`（实线 2px、虚线 1px）。虚线的那一圈正好是实线同侧**靠内那 2px**。
线永远画在伪元素或 overlay 矩形上，**不写 `td` 自身的 border**——那会改布局，也画不出格外的那几像素。

## 二、四条不变量（每条都对应一次真实故障）

1. **格内顺序定胜负，整格不提层。**
   虚线必须压住实线（虚线看见的是实线靠内那 2px），只靠格内层的先后。
   ‼️ 复制区格子不许提整格 `z-index`：一提，它的不透明底色会压过**邻格**的选区边框，把 3px 咬掉 2px
   （真机同坐标差分：相邻场景丢 96 个绿像素；不提层为 0，而“虚线压住实线”逐像素不变）。
2. **一条边一个变量、一个类。**
   角上的格子同时挂两个边类，变量各管一条、互不覆盖；合并成一条规则会给四条边一起上色，内部格挂一个类就长出一整圈线。
3. **虚线缝要垫该格自己的底色。**
   虚线线段之间透明，不垫底就会露出底下的实线/格线。垫底必须取该格的有效底色（只读 / 可编辑 / 假删除三档），
   写死表格底色会在可编辑列露一条更暗的 2px 槽；复制区落在选区内时还要再叠一层选区填充色。
4. **只给外圈挂边，“内部无线”是结构上必然。**
   选区与复制区都只给外圈那一排格子上边，内部格什么都不挂。
   代价（已知且接受）：紧贴时邻居的实线会压住虚线约 1px；**只接受 1px，2px 就是 bug**。

## 三、层级与布局

- 旧的格内两层：实线 `::before(1)` < 虚线 `::after(2)`；
- 现行 overlay 两层：滚动层 `z-41`、钉住层 `z-52`；表头 `z-60`；钉住数据列 `z-50`；
- 钉住层横滚用 `sticky left-0` **原生跟随**，不用 JS 写 `transform`（会比合成器滚动晚一帧 → 边框抖）；
- **握把列是 `cell-pinned`（z-50）**：滚到握把上的轮廓会被它的不透明底色盖住，所以“包住握把”的那一小段必须画进钉住层；
- 冻结列边界的“格外 1px”会被邻格盖掉 → 只有冻结区边界格需要再提一级；复制区一律不许提层；
- 布局语义：整行选区**不画右边缘**；末行末列不撑出滚动区；选区包含第一列时轮廓向左包住握把（填充不包）。

## 四、为什么不是这些“直觉做法”

| 直觉做法 | 问题 |
| --- | --- |
| `outline: 3px` | 四边同宽、按 border box 算，做不出“一条边一个类”，内部会被整圈上色 |
| 整格 `z-index: 10` 让虚线永远最上 | 会压过邻格边框，2px 被咬掉（差分实测） |
| `border-spacing` 的背景缝当格线 | 本表格线在格自身 border 上，两种网格模型下“格外 1px”的算法不同 |
| 垫纯白 / 固定底色 | 本表三档底色，写死会在可编辑列露暗槽 |
| 用四条独立线拼虚线框 | dash 相位只在左上角对得上，其余三角会“截断”；整格一个 `border-style: dashed` 盒才四角完整 |

## 五、当前实现落点

- **纯几何**：`selectionOverlay.ts` —— 无 DOM、无 React，输入实测尺寸，输出两层矩形，单测覆盖边界与握把；
- **渲染**：`SelectionOverlayView.tsx` —— 作为 `BaseTable` 外壳的子节点渲染，按 `fill / ring / copy` 三类矩形渲染，全部 `pointer-events: none`；
- **接线**：`useSelectionOverlay.ts` —— 量高度、算几何；`ActionsTable` 只取模型，不再逐格挂选区类名，`BaseTable` 负责外壳（滚动框）与 overlay 的挂载。
