# 表格选区与拖选性能方案（A-full）

> 状态：已确认执行
> 基线提交：`2e42473 perf(style): 精简样式表并修复选区边框拐角缺口`
> 范围：只改「选区渲染链路」（选区/拖选/复制高亮）。表格结构、滚动方式、量宽、行高、reveal 坐标沿用现状。

## 0. 目标

把选区与复制高亮从「每个单元格挂类名 + 伪元素画边」改为**单层 overlay 渲染**，让拖选热路径不再改动任何单元格 DOM、不再产生表格布局（Layout）成本；同时只在有数据收益的地方做 React / TanStack 优化。

验收以三项 trace 指标为准，不只看帧时间：

| 指标 | 当前基线（待阶段 0 复测确认） | 目标 |
|---|---|---|
| `Layout` 次数 / 耗时 | 6 次 / ~32ms（5×5、8 步） | **0 次** |
| 长任务数 | 1–4 个 / 最长 75–100ms | **0 个** |
| `HitTest` 耗时 | ~77ms | ≤ 40ms |
| `Paint` 次数 / 耗时 | 12 次 / ~56ms | ≤ 7 次 / ≤ 35ms |
| 本地测试 | 272 通过 | 全绿 |
| 视觉 | — | 冻结区/普通区/跨边界/末行末列/活动格/复制虚线一致 |

## 1. 可直接复用的既有结论

以下都是在本项目真机上验证过的，不再重复试错：

### 1.1 选区用单层 overlay（已验证）

原型阶段实测：连续 5×5 拖选 **0 长任务、0 Layout**。原理是选区变化只改 overlay 的若干 `div` 的几何/颜色，不碰 `<td>`：

- `pointer-events: none`，不参与命中测试；
- 不参与表格布局（绝对定位）；
- 填充/轮廓/活动格挖洞全部由「行高 × 行下标、列宽累加」算出，不读 DOM。

### 1.2 基表的三条 CSS 性能约束（已生效，保留）

都在 `SigilLoadout/frontend/src/style.css`：

1. 基表行**关闭** `content-visibility`（display-lock 会让指针移动的 HitTest/PrePaint 变贵）；
2. 基表行**关闭** `hover:bg-*` 与 `transition-colors`（格子不透明、hover 不可见，却会造成整行重绘）；
3. 选区伪元素**常驻**，不按需 `content:none`（伪元素增删本身会触发表格重排）。

### 1.3 边框绘制方式（拐角缺口修复后的结论）

- 表格用 `border-separate border-spacing-0` + `table-layout: fixed` + 显式列宽；
- 需要「画边」时，**宽度按边给（0 或 3px）、颜色统一**；四边都 3px 只在边上换颜色会在拐角产生 45° 颜色斜切（行交界 V 形缺口）；
- 交互过程中**不改** `td/tr` 的 `border/padding/width/font`（这些是表格布局输入）。overlay 不涉及这些。

### 1.4 诊断口径（固定）

- CDP trace：`Tracing.start` categories `toplevel,devtools.timeline,blink,cc,renderer.scheduler`；统计 `Layout`、`UpdateLayoutTree`、`HitTest`、`Paint`、`Layerize`、`PaintArtifactCompositor::Update`；
- 像素级验证：`Page.captureScreenshot` 配合 `Emulation.setDeviceMetricsOverride`（DPR 2）放大截取交界处；
- 交互/几何：`tools/debug/cdp-probe.mjs --expr "..."`；滚动/选区状态直接读 DOM 与 `table.getCellSelectionBounds()`。

## 2. 方案细节

### 阶段 0：基线记录

1. 记录三组 trace：连续 5×5（199 步）、离散 5×5、行号拖选；记录复制后拖选；
2. 截取 6 张基准图：冻结区选中、普通区选中、跨边界选中、末行末列、活动格、复制虚线；
3. 记录 `clientHeight/scrollHeight/tbody 高度/thead 高度/各列宽`，确认行高、表头高与列宽来源。

### 阶段 1：纯几何模块（先单测，不接 UI）

新增 `SigilLoadout/frontend/src/components/actions-table/selectionOverlay.ts`，零 DOM、零 React。

**输入**

```ts
type GeometryInput = {
  columnLefts: number[]   // 显示顺序；内容坐标（行头之后从 0 起算）
  columnWidths: number[]
  headerHeight: number    // 实测 thead 高度（当前约 41）
  rowHeight: number       // 实测行高（当前约 27）
  rowHeadWidth: number    // 行号 40 +（可排序时）握把 32
  gripWidth: number       // 0 或 GRIP_WIDTH
  pinnedColumnCount: number
  rowCount: number
  columnCount: number
}
type Bounds = {minRowIndex; maxRowIndex; minColumnIndex; maxColumnIndex}
```

**输出**

```ts
type OverlayModel = {
  scrolled: {fill: Rect[]; ring: Rect[]; copy: Rect[]} // 普通区层
  pinned:   {fill: Rect[]; ring: Rect[]; copy: Rect[]} // 钉住区层
}
```

**几何规则（逐像素，写进单测）**

- 填充矩形：`x = columnLefts[minCol]`、`y = headerHeight + minRow * rowHeight`、宽高按区间累加；
- 活动格挖洞：填充矩形减去活动格矩形（最多 4 块）；
- 轮廓：每条边一个 3px 线矩形：左 `x-2`、右 `x+w-2`、上 `y-2`、下 `y+h-2`，长度 = 宽度/高度 + 3；
- 贴表格右/下边时，右/下轮廓各收回 1px（避免撑出滚动区）；
- 钉住列边界：把一段选区切成两段，切开处**不画竖边**；两段分别进入 `scrolled` / `pinned`；
- 握把：选区包含第一列时，轮廓向左扩 `gripWidth`（填充不扩）；
- 复制虚线：与轮廓同一套分段/边标记，线宽 2px、`inset = 1px` 的坐标；
- 单测至少覆盖：单格、跨钉住边界、多片选区、活动格挖洞、末行末列、握把、空选区、行列数变化。

### 阶段 2：Overlay 组件

新增 `SigilLoadout/frontend/src/components/actions-table/SelectionOverlay.tsx`。

**挂载**

- `createPortal` 到 `scrollRef.current`（= `table.parentElement`，现有滚动框）；
- 仅 `measured` 后渲染；宽高用阶段 0 的实测值（`thead` / `tbody` rect 求），不写死常量。

**两层**

| 层 | z-index | 说明 |
|---|---|---|
| 滚动层 | 41（现有 `--z-edge` 同档） | 内容坐标，随原生滚动；被冻结列盖住 |
| 钉住层 | 52（高于 `--z-pinned-edge` 51、低于表头行 60） | 横向滚动时 `translateX(scrollLeft)` 跟随，一次 style 写，不触发布局 |

- 两层都 `pointer-events: none`；
- 钉住层用 `scroll` 被动监听写 `transform`（不读 DOM）；
- 填充 = 一个 `div`/矩形，背景 `color-mix(in srgb, var(--cell-fill) var(--cell-fill-alpha), transparent)`（沿用现有变量）；
- 轮廓 = 每条边一个 `div`（`background: var(--cell-select)`），**不用 `border`**（避免拐角斜切与任何盒模型变化）；
- 复制虚线 = 每条边一个 `div`，`background-image: repeating-linear-gradient(...)`（2px 实/空），缝隙底色先用 `var(--background)` 垫一层。

**测试辅助属性**

- 矩形元素加 `data-overlay="fill|ring|copy"` 与 `data-rect="x,y,w,h"`；
- 组件外层加 `data-selection-overlay`，便于集成测试断言几何。

### 阶段 3：接线与删旧

修改 `SigilLoadout/frontend/src/components/ActionsTable.tsx`：

1. 由 `sheetColumns` + `columnSizing` 算 `columnLefts`/`columnWidths`；实测 `headerHeight`/`rowHeight`（`useLayoutEffect` + ResizeObserver，量一次）；
2. `bounds = table.getCellSelectionBounds()` → 几何 → 传入 `SelectionOverlay`；
3. 活动格：从 `cellSelection` 最后一段的 anchor 行列 id 求得下标 → 传给几何模块挖洞；
4. 删除 `rowSelectionKey` 的 import 与使用；`ActionRowView` 不再接收 `edgeKey`；
5. `selectionClass` 只保留 `cell-active` 标记（`useReveal` 仍按 `td.cell-active` 定位），不再输出 `cell-selected`/`cell-edge-*`；
6. `cellCopyRing` 暂时保留逐格（复制是低频操作，且虚线需要按格底色垫底）；后续如需迁移再单独做。

修改 `SigilLoadout/frontend/src/components/actions-table/ActionRowView.tsx`：

- 删除 `edgeKey` prop；
- 单元格 `className` 去掉 `selectionClass(...)`，保留 `columnCellClass`、`cell-focus`、`cell-active`；
- `rowSelected` 仅保留给行号格。

修改 `classes.ts` / `selection.ts`：

- 删除 `selectionClass`、`rowSelectionKey`；
- 保留 `cellCopyRing`、`ringClasses`（复制虚线还在用）、`handleCellClass`。

修改 `style.css`：

- 删除：`.cell-selected` 底色、`.cell-edge-*` 相关规则、伪元素归属里针对选区实线的部分、末列/末行 `::before` 收回规则（overlay 自己处理）；
- 保留：`cell-copy-*`、`cell-focus`、提层 token（`--z-edge/--z-pinned/--z-pinned-edge`）、基表性能三件套、主题与其它页面规则。

### 阶段 4：测试改造

- 新增：`selectionOverlay.test.ts`（阶段 1 单测）+ `SelectionOverlay.test.tsx`（portal/两层/矩形数量）；
- 修改：`ActionsTable.selection.test.tsx` / `rows.test.tsx` / `keys.test.tsx` 中所有 `cell-selected` / `cell-edge-*` 断言 → 改断言 overlay 的 `data-rect` 或选区状态；
- 保持不变：复制/粘贴/撤销/编辑/键盘/行拖行为测试；
- `style.test.ts` 同步删除已删规则断言，保留提层/焦点/主题/复制约束。

1. `pnpm --dir SigilLoadout/frontend run typecheck`；

5. **止损**：若 `Layout ≠ 0` 或有长任务、或截图出现框错位/被遮住 → 回退到 A-min（只把轮廓/复制虚线放 overlay，填充保留逐格 `inset box-shadow`），不再继续叠加机制。

### 阶段 6（条件触发，不默认做）

只有阶段 5 不达标时才做，做完必须重新量收益：

- **命令式拖选**：`mousemove` 期间只用 ref 更新 overlay 几何，不 `setState`；`mouseup` 提交一次 `cellSelection`。需要接管 TanStack 的选区扩展手势，改动面较大，必须单独验收；
- **TanStack 订阅下沉**：overlay 改为 `table.Subscribe` / atom 选择器只订阅 `cellSelection`，父级 `ActionsTable` 不因选区重渲；同时把 `useReveal` 改成几何计算（去掉 `cell-active` 依赖）。参考：TanStack `Table State (React)` 指南与 React Compiler 指南（链接见附录）。

## 4. 实施记录（2026-10-17）

已按 A-full 完成，阶段 6（命令式拖选 / TanStack 订阅下沉）**不需要**：连续拖选已 0 长任务。

| 项目 | 改前（8 步 trace） | 改后（199 步 trace） | 结论 |
|---|---|---|---|
| `Layout` | 6 次 / 32ms | 8 次 / 5ms（≈0.04ms/步） | 不再有整表重排 |
| 长任务（连续 5×5，149 步） | 1–4 个 / 最长 75–100ms | **0 个** | 达标 |
| `HitTest` | 77ms / 8 步（≈9.6ms/步） | 808ms / 199 步（≈4.1ms/步） | 命中测试下降 |
| `Paint` | 12 次 / 56ms | 43 次 / 26ms（≈0.13ms/步） | 大幅下降 |
| 测试 / typecheck | 272 通过 | **279 通过** / `tsc` 干净 | 达标 |

实现要点（与上面方案一致，外加两处落地修正）：

1. `selectionOverlay.ts`：纯几何；`buildOverlay` 输出 `scrolled` / `pinned` 两层的填充、轮廓、复制虚线矩形；含活动格挖洞、钉住列切段、整行选区右边缘不画、握把列向左包 `GRIP_WIDTH`。
2. `SelectionOverlayView.tsx`：portal 到滚动框；滚动层 `z-41`、钉住层 `z-52`；钉住层 `translateX(scrollLeft)` 跟随；全部 `pointer-events: none`。滚动框补了 `position: relative` 作为定位原点。
3. `ActionsTable`：新增几何输入（列左缘累加 + 实测表头高/行高）、`copyAreas` 映射（复制源 id → 显示下标）、测试投影（`data-selection-bounds` / `data-active-cell` / `data-copy-bounds`）。
4. 删除：`rowSelectionKey`、`selectionClass`、逐格 `cell-edge-*` / `cell-selected` / `cell-copy-*` 渲染与 CSS、`cellCopyRing` / `ringClasses`、`--cell-under`。复制虚线改为 overlay 画（原先逐格 `::after` 会被 overlay 盖住）。
5. 测试改为断言**选区语义**（投影区间），不再断言类名；几何单测 8 条覆盖单格/跨钉住/挖洞/末行末列/握把/复制。
6. 钉住层的横滚跟随**不用 JS**：`scroll` 事件写 `transform` 会比合成器原生滚动晚一帧 → 横滚时边框抖。改为「外层撑满内容宽 + 内层 `sticky left-0`」，由滚动线程原生保持，与冻结列同节奏；实测 45 帧平滑横滚里边框与目标格偏差恒定（0 抖动），纵滚按行正常跟走。
7. 已知视觉差异：选区填充画在文字层之上（8% 叠色，截图确认可接受）；选中格的焦点环不再被 CSS 抑制（overlay 的边在其上，影响很小）。
