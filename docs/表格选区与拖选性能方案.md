# 表格选区与拖选性能方案（A-full）

> 状态：已实施（2026-10-17），后续修正在第 3 节。
> 范围：只改「选区渲染链路」（选区 / 拖选 / 复制高亮）。表格结构、滚动方式、量宽、行高、reveal 坐标沿用现状。

## 0. 目标

把选区与复制高亮从「每个单元格挂类名 + 伪元素画边」改为**单层 overlay 渲染**：

- 拖选热路径不碰任何 `<td>`，不产生表格布局（Layout）；
- 几何用纯函数算，可单测；
- React / TanStack 优化只在有数据收益的地方做。

验收以 trace 指标为准（8 步连续 5×5）：

| 指标 | 改前 | 目标 |
| --- | --- | --- |
| `Layout` | 6 次 / 32ms | 0 次 |
| 长任务 | 1–4 个 / 最长 75–100ms | 0 个 |
| `HitTest` | ≈9.6ms/步 | ≤ 40ms 总量级 |
| `Paint` | 12 次 / 56ms | ≤ 35ms |
| 测试 / typecheck | 272 通过 | 全绿 |

## 1. 已验证的结论（不再重复试错）

- **单层 overlay 可行**：原型阶段连续拖选 0 长任务、0 Layout。原理是只改 overlay 若干 `div` 的几何/颜色，不碰格子；
  `pointer-events: none` 不参与命中测试，绝对定位不参与表格布局，几何全靠“行高 × 行下标、列宽累加”算，不读 DOM。
- **基表三条 CSS 约束**：行关闭 `content-visibility`（display-lock 让 HitTest/PrePaint 变贵）、关闭行 `hover` 与 `transition`
  （整行重绘）、交互中不改 `td/tr` 的 `border/padding/width/font`（表格布局输入）。
- **边框绘制**：`border-separate border-spacing-0` + `table-layout: fixed` + 显式列宽；画边时按边给宽度、颜色统一，
  四边同宽换颜色会在拐角产生 45° 斜切。
- **诊断口径**：CDP trace（`Layout` / `UpdateLayoutTree` / `HitTest` / `Paint` / `Layerize` / PAC）、
  DPR2 放大截图、`cdp-probe.mjs` 读 DOM 与 `getCellSelectionBounds()`。

## 2. 方案

### 2.1 几何层（纯函数，零 DOM / 零 React）

输入：实测列左缘 / 列宽 / 表头高 / 行高、行头宽、握把宽、钉住列数、行数 / 列数，以及选区 bounds。
输出：`scrolled` 与 `pinned` 两层各自的 `fill / ring / copy` 矩形。

规则：

- **填充**：按下标区间算矩形；活动格从填充里挖洞（最多 4 块）；
- **轮廓**：每条边一个 3px 矩形，贴表格右/下边时各收回 1px；
- **钉住列切段**：一段选区在钉住边界切成两段，切点不画竖边，两段分别进入两层；
- **握把**：选区包含第一列时轮廓向左扩 `gripWidth`（填充不扩），扩出来的那一小段进**钉住层**；
- **整行选区**：不画右边缘；
- **复制虚线**：2px，右/下进格 2px；与轮廓同一套分段与边标记，线宽和 inset 不同；
- **单测覆盖**：单格、跨钉住边界、多片选区、活动格挖洞、末行末列、握把、空选区。

### 2.2 渲染层（portal + 两层矩形）

- `createPortal` 到滚动框（`table.parentElement`），measured 之后才渲染，宽高用实测值；
- **滚动层 `z-41`**：内容坐标，随原生滚动，被钉住列盖住；
- **钉住层 `z-52`**：高于钉住列 `z-50`、低于表头 `z-60`；用「外层撑满内容宽 + 内层 `sticky left-0`」跟随，
  由滚动线程原生保持，**不用 JS 写 `transform`**（晚一帧会抖）；
- 两层都 `pointer-events: none`；填充/轮廓/复制各自渲染成绝对定位矩形；
- 轮廓用背景色矩形，不用 `border`（避免盒模型变化与拐角斜切）；
- 矩形不带测试属性；集成测试的断言入口是 `ActionsTable` 的隐藏投影 `data-selection-bounds` / `data-copy-bounds`，几何本身由 `selectionOverlay.test.ts` 的纯函数用例锁住。

### 2.3 接线与删旧

- 几何输入：表头各格**实测宽度**（`th.offsetWidth`，含行号/握把）+ 表头高 / 行高，`useLayoutEffect` 量一次、`ResizeObserver` 跟容器尺寸重算 —— **不从 `columnSizing` 反推**：窄表被 `min-w-full` 按容器宽拉伸后，列宽与 state 不是一回事；
- 选区：`table.getCellSelectionBounds()`；活动格由 anchor 的行列 id 求下标后交给几何挖洞；
- 复制区：复制源的 id 集合按显示顺序映射成下标区间；
- 删除逐格选区的全部机制：`cell-selected`、`cell-edge-*`、`cell-copy-*` 类与 CSS、`rowSelectionKey`、`selectionClass`、
  `cellCopyRing`；`selectionClass` 只保留 `cell-active`（`useReveal` 仍按它定位）；
- 行号 / 握把 / 钉住列仍由表格结构与 CSS 负责，不进几何模型。

### 2.4 复制虚线的落地修正

- 逐格一个 `border-style: dashed` 盒（拆四条线只有左上角相位对得上，其余三角截断）；
- 右/下进格 2px：盒子 `left/top = 格 - 1`、宽高 `= 格 + 1`；
- 缝隙底色 = 该格有效底色（只读 / 可编辑 / 假删除），落在选区内再叠选区填充色；
- 底色只铺在边框那一圈（mask 环），内部挖空，避免整块蒙一层。

### 2.5 验收与止损

1. `typecheck` → `test` → 部署；
2. 重跑三组 trace（连续 5×5 / 离散 5×5 / 行号拖选）与 6 张截图，逐项对比第 0 节；
3. **止损**：若 `Layout ≠ 0`、有长任务、或截图出现框错位/被遮住 → 回退到 A-min（只把轮廓与复制虚线放 overlay），
   不在失败方案上继续叠机制。

### 2.6 条件项（不默认做）

- **命令式拖选**：`mousemove` 期间只用 ref 更新几何，`mouseup` 才提交选区；
- **TanStack 订阅下沉**：overlay 只订阅 `cellSelection`，父组件不因选区重渲。

两者都需要扩大改动面、单独验收；实测连续拖选已 0 长任务，所以不做。

## 3. 落地结果

| 项目 | 改前（8 步） | 改后（199 步） | 结论 |
| --- | --- | --- | --- |
| `Layout` | 6 次 / 32ms | 8 次 / 5ms（≈0.04ms/步） | 不再整表重排 |
| 长任务（149 步） | 1–4 个 / 最长 75–100ms | **0 个** | 达标 |
| `HitTest` | ≈9.6ms/步 | ≈4.1ms/步 | 下降 |
| `Paint` | 12 次 / 56ms | 43 次 / 26ms（≈0.13ms/步） | 大幅下降 |
| 测试 / typecheck | 272 通过 | 全绿 | 达标 |

后续修正（2026-10-18）：

- 选区的 React 接线抽成 `useSelectionOverlay.ts`，`ActionsTable` 从 997 降到 917 行；
- 握把格去掉与 `sticky` 冲突的 `relative`（曾整列压到 `config` 上）；“包住握把”的轮廓画进钉住层，才压得住 z-50 的握把格；
- 复制虚线由四条渐变带改为 mask 环（像素差 maxDelta = 1/255）；
- 删除 `corners` 角块等死概念（DPR1/DPR2 逐像素证明无差异）。
