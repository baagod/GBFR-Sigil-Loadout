# 表槽的地址由语义锚点解析，不写死 RVA

原生在装钩子之前，用一段**指令序列**（而不是地址常量）定位"发布技能表"的那处代码，再解出它的 RIP
相对位移，得到表槽与缓冲区指针字段的 RVA。锚点三段：唯一的"行循环"锚点（`imul rdi,rsi,0x34;
add rdi,rbx; vxorps`——12 字节，既无 rel32 也无 rip 位移），加上它前面 0x800 字节窗口里恰好各出现
一次的那两条发布指令。五道条件任一不成立就**拒绝解析**：三处命中数各为 1、两个目标正好差 8、
都落在可写非执行段。

写死 `module_base + 0x7028F20` 省事得多，但那正是会写到别人家表上的那条路。表槽沿用本项目既有的
做法（`layout_resolver`：语义锚点 + 字节预检 + fail-closed）。

## Considered Options

- **写死 RVA**：最省事也最脆——游戏一更新就危险。
- **只拿那对发布指令当签名**（20 字节，两个 disp32 通配）：实测在 2.0.6 的 `.text` 里命中 **23 处**，
  而判据要求"恰好 1 处"，于是它会**永远拒绝**、一条路都走不通。唯一性必须实测，不能靠"应该"。

## Consequences

- 换版本时锚点对不上**只是退化**：不解析、不写，编辑在游戏下一次解析或重启后生效。
- 行数不写死在原生：表的形状由托管侧从归档读出的那张表定义（"8 + 52×行数 == 长度"这个关系成立即可），
  所以行数变了不用改原生一个字。
- 锚点在 `InstallHooks()` **之前**解析：我们自己的 safetyhook 会改写 `.text`，锚点要在没被改写的字节上匹配。
