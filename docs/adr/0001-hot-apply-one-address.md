# 热应用只写表槽那一个地址，不再扫描内存找别的表

游戏把解析好的技能表发布在一个固定槽里（**表槽**）；运行中的编辑只写它指向的那一份（**活表**）。
定位一次实测 **0 ms**（读表槽），1 行编辑写进去 **2 ms**。此前那条路是"扫过全部内存、把所有内容
相同的表都写一遍"：定位一次 **6596 ms**，而且要不要重扫取决于上次找到的地址还有没有效——1 份时
8 ms，2 份时有时要重扫 7.8 s。

配套删掉的是扫描本身（`TableLocator.cs`，279 行）。它从这条机制上线起**一次都没跑过**：四个会话里
每次应用都是 `… in 2–4 ms; no memory was scanned`，日志里从没出现 `located … copy/copies`。
而它证明不了唯一重要的那件事——"这块缓冲区就是游戏在用的那块"静态证不出来。

## Considered Options

- **保留扫描**：保险是"锚点失效也能写"，代价是 279 行、一条 5–6 秒的慢路径，以及"第一次点击要不要
  重扫"这个永久存在的问题。
- **只在锚点失败时才扫**（本 ADR 之前的形态）：它从未被触发，所以这条保险自身的正确性也没有任何实测支撑。
- **只扫、不解析锚点**（更早的形态）：见上面那组 8 ms / 7.8 s 的数字。

## Consequences

- 锚点解析失败、或四道闸任一不过时，**这一局内存里那份表不变**。表在写之前已经重新注册，所以游戏
  下一次解析、或重启后照样生效；拒写会落一行明确日志
  （`hot apply: FAIL - the native slot write refused (code …)`）。
- 没有地址缓存，也就没有"缓存失效"。
- 写的是**行**：1 条编辑 = 52 字节，而不是整张表 328,648 字节。
