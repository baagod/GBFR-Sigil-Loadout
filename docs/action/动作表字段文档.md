# 动作表 · `system/player/data/plXXXX/plXXXX_action.msg`

> 角色**技能/攻击/派生动作的静态参数表**。每个动作一条记录。
> 本文所有数字均从游戏归档直出实测；**推断处单独标注**，不与事实混排。
> 相关：`docs/角色动作探索汇总.md`（三层结构总览与运行时能力边界）

---

## 1. 位置与命名

```
system/player/data/pl1000/pl1000_action.msg     ← 炎帝（珀西瓦尔）
system/player/data/pl0000/pl0000_action.msg     ← 古兰
system/player/data/pl0400/pl0400_action.msg     ← 伊欧
...
```

- 每个角色**一个文件**，文件名 = `<角色码>_action.msg`
- 角色码见 `plXXXX`（`pl1000` = 珀西瓦尔，`pl2100` = 卡莉奥丝特罗 ……）
- 与它同目录的 `plXXXX.msg` 是 **CharacterInfo**（技能位 → 动作 id 的映射），**不是**本表

## 2. 文件结构（msgpack）

| 项 | 实测 |
|---|---|
| 格式 | msgpack（`.msg`），**不是** `.tbl` |
| 根 | `map32`，**键名全部是重复的 `ActionInfo`** |
| 记录 | 每条记录一个 `map`，字段**全是字符串**（数值也以字符串存） |
| 炎帝记录数 | **35** 条 |
| 字段数 | **87** 个/条（同文件内所有记录键一致） |

> ⚠️ **根键名重复**（全是 `ActionInfo`）→ 转成 JSON 会**丢记录**，必须按 msgpack 的 entries 数组处理。
> 编码器用 `refs/GBFR-Tool---Data-Table-Editor/core/msgpack.js` 可做到**字节级往返一致**。

## 3. 记录与 id

- `id_` 是动作编号，**被别的表/字段引用**（`branch*`、`derivedId_`、CharacterInfo 的技能位等）
- 炎帝的 id 分布：`1~8`（技能）、`40`（技能强化版）、`100/101/111/121`（连段）、`200/201/300~321`（空中/蓄力）、`400/410/500/510/700`（跳跃/防御）
- **id 不是连续数组下标**，是纯 id

### 3.1 命名与术语（两个易混点）

**① `saveMotIdNN_` 到底叫什么？**

| 来源 | 叫法 |
|---|---|
| 官方字段名 | `saveMotId01_` —— 字面是 "**save motion id**" |
| 官方说明 | *"Motions being called by this action"* |
| `refs/GBFRModToolV3.4` | 「**动作ID01** / 调用的动画ID」 |
| `refs/GBFR-Tool---Data-Table-Editor` | 「**动作ID01**」 |

⚠️ **两个中文工具都译作"动作ID"，但它指向的是 `pl/plXXXX/plXXXX_XXXX.mot`（motion 号），
不是本表里的 `id_`。** 本项目的叫法：**motion 号**。

**② `actionName_` 与"技能中文名"是两回事**

| 名称的来源 | 怎么查 | 覆盖率（实测） |
|---|---|---|
| **技能中文名**（如"撕裂""力量"） | `abilityTag_`（`AB_PL1000_04`）→ 游戏自带翻译表 `text/<lang>/text.msg` 的 `TXT_AB_*` | **258/268**（含姬塔 `PL0100`→`PL0000` 回退规则） |
| **动作区分名**（如"移動攻撃（溜め）"） | `actionName_` 本身（日文开发者命名） | 部分动作为空 |

> **`actionName_` 不是完全没用** —— 它是**同一技能多个变体之间唯一的区分标签**
> （如 `移動攻撃` / `移動攻撃（溜め）` / `移動攻撃（即時発動）` / `移動攻撃（リンクアタック）` 四条动作
> `abilityTag_` **全为空**，只能靠 `actionName_` 区分）。
> 但**游戏逻辑不读它**（官方："可能未使用"），所以改了不影响行为。

> ⚠️ **对参考工具"动作名称"列的提醒**：该列的中文名**不能从本表推出**。
> 例：`pl2900` 的 `id=210` 在本表里是 `abilityTag_ = (空)`、`actionName_ = 移動攻撃`，
> 而工具那一列显示「**永暗一闪**」—— 与字面无关。**技能类动作**的官方中文名可从游戏翻译表查到（上表），
> 但**非技能动作那批是工具作者自己整理的对照表**，可信度需打折。

### 4.1 `supportEffectList_` 详解（Buff 层）

**结构**：`[数量 N, (BuffId, p1, p2, p3, p4, p5, p6) × N]`。
实测长度只有 **`1 / 8 / 15 / 22 / 29`** 五种（= N 为 0~4）。

**触发**：该动作的 motion 里 **`Flag1:2`** 被调用时施加。
**已实测**：给撕裂写入 `4039598841` + 在 flags 轨加 `Flag1=4` → **头顶出现霸体图标**。

**6 个参数与"含义标签"按位置一一对应**（标签取自人工对照表，见下方来源）：

| BuffId | 名字 | 参数标签 `[p1..p6]` | 炎帝实测值 |
|---|---|---|---|
| **`4039598841`** | **霸体(自身)** | `[持续时间(s), , , , 1, 1]` | 力量 `[0.5, 1, 3, 1, 1, 1]` |
| `2124637228` | 攻击(全队) | `[百分比, 持续时间(s), , , 1, 1]` | `[15, 30, 0, 0, 1, 1]` |
| `1920597266` | 防御(全队) | `[百分比, 持续时间(s), , , 1, 1]` | `[10, 30, 0, 0, 1, 1]` |
| `389827112` | 追伤(自身) | `[持续时间(s), 追伤百分比, 延迟帧数, , 0-1, 0-1]` | `[30, 30, 7, 1, 1, 1]` |
| `1325296888` | 强壮 | `[百分比, 持续时间(s), , , 1, 1]` | `[40, 30, 0, 0, 1, 1]` |
| `2748354252` | （两份中文表都未收录） | — | `[30, 0, 0, 0, 1, 1]` |

**炎帝整张动作表只用到这 6 个 BuffId。**

**写回规则**：只改第 2~7 个位置（6 个参数值）；
**第 1 个（数量）和第 2 个（BuffId）绝对不能动** —— 改 BuffId 等于把这条动作改成施加另一个 Buff。
值在 msgpack 里是 `fixstr` 字符串，写回也要写字符串。
实测：改一个值 → 78002 字节的文件里**只有 1 个字节变化**，还原后 SHA-256 完全一致。

> **来源与交叉验证**
> - 名字与参数标签来自 **`translations/buff_db.json`**（第三方人工对照表，见 `refs/GBFR-Tool---Data-Table-Editor/editors/buff.js` 头部的研究日志）。
>   该表收录 83 个不同哈希（`generic` 37 条 + `specific` 16 个角色 46 条）。
> - 该工具**独立实测**的结论与本项目一致：
>   - Buff 数值只在 `player/data/<plXXXX>/<plXXXX>_action.msg`，**不在任何 `.tbl`**
>   - 全量扫 288 张 `.tbl` 里所有能装 32 位值的列 → 83 个哈希**命中 0**
>   - 全游戏 259 处效果实例、78 个不同哈希 → **62 个（79.5%）有名字**，覆盖 **228/259 行（88%）**
>   - 参数标签为 `1` / `1(Default)` 的位置，**443/443 出现值恰好是 1**（佐证"按位置对应"）
> - **本项目独立验证**：`4039598841` → 实测给撕裂加上后头顶出现**霸体**图标，与表中 `霸体(自身)` 吻合 ✔

### 实测经验（炎帝）

| 事实 | 依据 |
|---|---|
| `F39CFDF5`（Type 0）= **只播第 1 个 motion** | 撕裂原本是 Type 0；把 `saveMotId02/03_` 填上力量的两段 → **完全不播** |
| `44DFF94D`（Type 6）= **按顺序播 3 段，可用** | 撕裂改成 Type 6 + `34a0 → 3451 → 3452` → **力量的效果与伤害都打出来了** |

| `E76CF662`（Type 22）**不可用** | 换成它之后 **按住技能会反复进连段**，且段没有顺序播放 |

## 6. `saveMotId01_` ~ `saveMotId12_` —— 动作调用的 motion

- 每个 motion 号对应**一整套文件**：

```
pl/pl1000/pl1000_3452.mot                      ← 动画
pl/pl1000/pl1000_3452_0_seq.bxm                ← 空占位（实测 ChunkEntryIndex = -1）
pl/pl1000/pl1000_3452_0_seq_edit_attack.bxm    ← 判定（伤害来源）
pl/pl1000/pl1000_3452_0_seq_edit_effect.bxm    ← 特效
pl/pl1000/pl1000_3452_0_seq_edit_flags.bxm     ← 时序位
pl/pl1000/pl1000_3452_0_seq_edit_se.bxm        ← 音效
pl/pl1000/pl1000_3452_0_seq_edit_ik / facialmotion / cloth / camera / eyecontrol / speed / vib
```

- **"在链里出现某个 motion 号" = 调用它那一整套文件** —— 这是把别的技能的伤害/特效搬过来的正确方式（不用复制任何轨道内容）
- **实际播几段由 `controlTypeHash_` 决定**（§5）；**超出槽数的填了也不会播**

### 炎帝三个技能的实测值

| `saveMotId` | 普通撕裂 `id=4` | 强化版 `id=40` | 力量 `id=6` |
|---|---|---|---|
| `01_` | `3400` | `34a0` | `3450` |
| `02_` | `-` | `34a1` | `3451` |
| `03_` | `-` | `34a2` | `3452` |
| `04_`~`10_` | `-` | `-` | `-` |
| `11_` / `12_` | 空串 | `-` / 空串 | 空串 |
| `controlTypeHash_` | `0xF39CFDF5` | `0xBCB2951A` | `0x4ABCF8AE` |

各 motion 的内容：

| motion | 属于 | 动画 | 判定 | 特效 |
|---|---|---|---|---|
| `3400` | 普通撕裂 | 50 KB | 3 条，**全在同一时刻** `0.7667`，倍率 `3.9` | `700` |
| `34a0` | 强化版 1 段 | 26 KB | 3 条 @`0.6833`，倍率 `3.9` | `710` |
| `34a1` | 强化版 2 段 | 13 KB | 1 条 @`0.0333`，倍率 `1.0` | `711` |
| `34a2` | 强化版 3 段 | 36 KB | 2 条 @`0.1333`，倍率 `1.0` | `713` |
| `3450` | 力量 1 段 | 19 KB | **无判定轨**（纯视觉） | `5200` |
| `3451` | 力量 2 段 | 8 KB | **无判定轨**（纯视觉） | `5210` |
| `3452` | 力量 3 段 | 41 KB | 3 条 @`0.1667`/`0.2167`/`0.6167`，倍率 `0.8`/`0.8`/**`5.8`** | `5220` + **`661`/`651`（`EffDataType=1`）** |

> **要点**：力量的**伤害 100% 在 `3452`**；`3450`/`3451` 只有特效。
> `3452` 也是炎帝唯一带 `EffDataType=1` 特效的 motion。

**`3452` 的 flags 轨 vs 撕裂 `3400`（实测，两个结构性差异）**：

| | 力量 `3452` | 撕裂 `3400` |
|---|---|---|
| **`Flag1="4"`**（Buff 触发位 bit2） | **`0.000`–`1.250s`** ✅ | **没有** ← **这就是撕裂原本不给霸体的原因** |
| **`Flag0="32"` 的条数** | **6 条**（0.083/0.217/0.283/0.350/0.417/0.583） | **1 条**（0.000–0.0167） |

**`Flag0` 第 5 位（值 `32`）≈ "这一段有攻击判定"** —— 炎帝 211 个 motion 全量统计：

```
有判定轨的 motion 中 81% 出现    无判定轨的只 3%
```

（条数不是 1:1 对应判定条数，但"有没有"高度吻合。相关位还有 bit4=16：56% vs 4%；bit6=64：31% vs 1%。）


## 7. 空值哨兵（同一文件里混用 4 种）

| 写法 | 含义 |
|---|---|
| `-` | 空（数值/引用类字段最常见） |
| `-1` | 空（`branch*` 系列用这个） |
| `""`（空串） | 空（`saveMotId11_`/`12_` 用这个） |
| `0` | 空或真正的 0（**无法区分**，需按字段判断） |

## 8. 实测：哪些改动真正生效

| 字段 | 改值 | 现象 |
|---|---|---|
| `supportEffectList_` + motion 的 `Flag1:2` 位 | ✅ | 撕裂头顶出现**霸体**图标 |
| `controlTypeHash_` + `saveMotId01~03_` | ✅ | 撕裂命中后**打出力量的效果与伤害** |
| `bulletType_` | ❌ | 炎帝不使用该字段；写入后无反应（含配套的 `fsmParam_` 追加） |
| `branchAtkHit_` | ⚠️ | **能触发**（角色会做一个动作），但**接出来的技能播不出来**；<br>且**新增动作记录不被游戏承认**（接招目标必须是原有 id） |

> 其余能力边界（flags 轨、effect 轨、attack 轨、FSM 挂载）见 `docs/角色动作探索汇总.md` §8。

## 9. 修改流程

1. 解包：`GBFRDataTools extract -i data.i -o <out> -f system/player/data/pl1000/pl1000_action.msg`
2. 改：用 `refs/GBFR-Tool---Data-Table-Editor/core/msgpack.js`（`parse` → 改 entries → `encode`）
   - **必须按 entries 数组处理**（根键名重复）
3. 放进 Mod（Reloaded-II）：`<Mod>/GBFR/data/system/player/data/pl1000/pl1000_action.msg`
   - 路径**必须**是 `GBFR/data/...` 开头，否则 loader 会整个跳过这个 mod
4. **重启游戏**生效（loader 只在启动时登记文件）
