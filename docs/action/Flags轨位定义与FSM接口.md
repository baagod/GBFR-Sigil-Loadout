# Flags 轨 · 位定义与 FSM 接口

> 本文记录 **`plXXXX_XXXX_N_seq_edit_flags.bxm`**（时序轨）里的 `Flag0` / `Flag1` 位含义，
> 以及"动作 → FSM"的接口。
>
> **来源标注**：
> - 🔵 **本项目实测** —— 在游戏里验证过现象
> - 🟡 **参考工具**（`refs/GBFRModToolV3.4` 的动作编辑器界面显示）—— 尚未在本项目逐位实测
> - ⚪ **官方文档**（nenkai/relink-modding）

## 1. Flags 轨的文件结构

```xml
<SeqRoot>
  <FlagsTrack SeqNum="N">
    <Seq LayerFlag="4294967295" StartTime="0.000000" EndTime="1.000000"
         Config="1" Flag0="0" Flag1="16" SysFlag="0" FreeArg="0 0 0 0" />
    ...
  </FlagsTrack>
</SeqRoot>
```

| 属性 | 含义 |
|---|---|
| `StartTime` / `EndTime` | 秒。最小粒度为 `0.016667`（= 1/60 秒，即 1 帧） |
| **`Config`** | **`1` = 触发（瞬间）**，**`0` = 持续** |
| `LayerFlag` | 始终 `4294967295`（全层） |
| **`Flag0`** | 位掩码 → 见 §2 |
| **`Flag1`** | 位掩码 → 见 §3 |
| `SysFlag` | 实测炎帝全为 `0`（少数文件有非 0，未定性） |
| `FreeArg` | 实测**恒为 `0 0 0 0`** |

- **加行**是允许的 —— 实测给撕裂加一行 `Flag1="4"` 就让它获得了霸体
- 参考工具的编辑器也把"**+ 添加行**"作为正常操作（新增行默认 `Flag1="16"` = 调用FSM技能）

### 🔵 本项目的独立统计（炎帝 211 个 motion 全量）

| 位 | 有判定轨的 motion 中出现率 | 无判定轨的 |
|---|---|---|
| **bit5（值 32）** | **81%** | **3%** |
| bit4（值 16） | 56% | 4% |
| bit6（值 64） | 31% | 1% |
| bit2（值 4） | 100% | 81%（几乎处处都有，判别力弱） |

→ **bit5 = "允许追加攻击命中"** 与我们统计到的"这一段有攻击判定"高度吻合 ✔（条数不是 1:1，但"有没有"很准）

### 🔵 bit16（值 65536）=「空中动作」的判别位（pl1000 全量实测）

pl1000 的 **222** 条 flags 轨里，只有 **13 条**含 `Flag0="65536"`，正是全部**空中动作**：

```
0080 0081
3200 3201 3203 3205 3206 320a 320b    空中□コンボ 1~3 段 + 長押し派生
3300 3302 3303                        空中△溜め攻撃链
3a00                                  ジャンプ上昇攻撃（"挑起"那一下）
```

**反例干净**：地面连段 `3000` ✗、能力 `3400` ✗、落地 `3103` ✗（空中连段 `320a` ✓）。

- 措辞要准 ✔：它是「**空中动作**」的判别位，**不是**严格的"空中**攻击**" ✗ —— `0080/0081` 看着不是攻击。
- 用法：要筛"空中动作"时，就看这条轨有没有 `Flag0=65536`。本项目的 effect `Scale` 实验就是靠它把范围从 167 条收窄到 5 个 motion 的。
- 顺带一条实测 ✔：这 13 个空中 motion 里**只有 5 个真的有 effect 轨**（`3200 3205 320a 3300 3a00`）；另外 8 个（`0080 0081 3201 3203 3206 320b 3302 3303`）在原版解包目录与随包 `data.zip` 里**都没有** effect 轨。

相关：[伤害触发时序·Flag0位5与Attack轨.md](伤害触发时序·Flag0位5与Attack轨.md) —— bit5 的语义、effect `Scale` 被运行时读取的实测、attack 轨"增删行有效 / 改字段值无效"。

| 20 | 1048576 | 激活 Vane 格挡效果 | 触发 |
| 21 | 2097152 | 未知(bit21) | 持续 |

### 交叉验证（三处，全部吻合）

| 位 | 参考工具 | 官方文档 | 🔵 本项目实测 |
|---|---|---|---|
| `Flag1` bit2（4） | 释放Buff | `supportEffectList_` 由 `Flag1:2` 触发 | ✅ 给撕裂加 `Flag1="4"` → **头顶出现霸体图标** |
| `Flag1` bit4（16） | 调用FSM技能 | FSM 由 `Flag1:4` 调用 | ⏳ 炎帝不使用该字段，未复现 |
| `Flag0` bit19（524288） | 命中后可触发 branchAtkHit | `branchAtkHit_` 由 `Flag0:19` 触发 | ✅ 触发成功（角色确实接了一个动作） |

> **与动作表字段的对应关系**（合起来才完整）：
> ```
> Flag1 bit2  → supportEffectList_   （施加 Buff）
> Flag1 bit4  → FSM                  （调用 FSM 技能）
> Flag0 bit19 → branchAtkHit_        （命中后自动接下一个动作）
> ```
> `supportEffectList_` 的 Buff 名与参数含义见 `docs/动作表字段文档.md` §4.1。

## 4. 动作 → FSM 的接口

### 4.1 调用方式

两种，**互不相同**：

| 方式 | 触发 | 用到的字段 |
|---|---|---|
| **`Flag1` bit4（调用FSM技能）** | 在该 motion 的 flags 轨里加一行 `Flag1="16"` | **没有**"用哪个 FSM"的字段：motion → FSM 的映射在游戏数据里**不存在**（见下面的更正） |
| **`Flag0` bit19 + `branchAtkHit_`** | 命中后自动开始**另一个动作** | `branchAtkHit_` 字段（动作表） |

> 🔵 实测：`branchAtkHit_` **能触发**（角色确实接了一个动作），但接出来的技能**播不出来**；
> 且**新增的动作记录不被游戏承认**（接招目标必须是原有 id）。
>
> ⚠️ **2026-xx 更正**：这段原先写"FSM 由该动作的 `bulletType_` 决定（映射写在 exe 里）"，**那个推论是错的**
> —— 试过按字母序 / 归档序 / 文件系统序去对 `bulletType_` 与 FSM 名单，**都对不上**，它不是简单下标。
> 之后的搜索把 7 个可能的方向全试过（动作表、flags 轨、FSM JSON、DB、exe 字符串……），结论是
> **motion → FSM 的映射不在这份游戏数据里**：它在参考工具自己的压缩字节码里（那是作者手写的对照表）。
> 所以界面上**不要试图显示"本动画关联的 FSM 是哪一个"** —— 显示不出来，也做不出来。
>
> **也不要在界面上断言"本动画会调用 FSM"**：那要靠 `Flag1` bit4 的含义成立才谈得上，而这一条本项目
> **没在游戏里复现过**（§3 的对照表里它是 ⏳），只有 🟡 参考工具的转抄 + 作者一句解释背书。
> 界面上能给的只是**原始证据**：flags 表里 `Flag1` 那一列 + 它的含义列（同样是 🟡），由人来判断。

### 4.2 参考工具的「可用 FSM」列表

参考工具在 motion 编辑器里会列出该角色/该动作**可加载的 FSM**（点一下即加载它的参数）。例：

- **`pl1800`**：`areaeffect_revive` `assist_mode_unique` `assist_mode_unique_atk_new` `barrier` `baseattack` `collapse_lv1` `collapse_lv2` `collapse_lv3` `disruption` `heal` `linkattack` `mehen` `snd_auto_base_1` `snd_auto_unique_1` `spare_body`
- **`pl2900`**：`ability01` `ability02` `ability02_02` `ability05` `ability07` `ability07_add` `ability08` `assist_mode_unique` `assist_mode_unique_atk` `assist_mode_unique_atk_build_a/b/c` `baseattack` `dive_combo_0`~`4` `finish_ball` `finish_ball_add` `finish_ball_fin` `linkattack` `malice_finish` `malice_shot` `normalfinish` `normalshot` `normalshot_1_1` `normalshot_2_1` `normalshot_3_1` `normalshot_3_2` `snd_auto_base_1` `snd_auto_stage_1` `snd_auto_unique_1` `spattack`

对应文件：`system/fsm/<角色>/<角色>_<FSM名>_fsm_ingame.msg`

> **这解释了"有些动作有 FSM、有些没有"** —— 可用列表是**按角色**给的，而**哪个动作调用哪个**由 exe 决定。

### 4.3 FSM 的参数结构（参考工具展示）

选中一个 FSM 后，界面分成三组参数：

**攻击参数**

| 参数 | 例（ability01 / ability05） |
|---|---|
| 攻击倍率 `attackRate_` | `2` / `1.7999999523162842` |
| 破防倍率 `breakRate_` | `1` / `0.800000011920929` |
| 奥义值倍率 `spArtsRate_` | `0.20000000298023224` / 同 |
| 击中停顿 `hitStopSecond_` | `1` / `0.00800000037997961` |
| 持续时间 `lifeSecond_` | `0.010000000149011612` / `0` |
| 延迟时间 `deleySecond_` | `0.05000000074505806` / — |
| 尺寸 `size_` | 空 |
| 属性 `element_` | `0` / `6` |
| 反应类型 `reaction_` | `1` / `0` |
| 击退倍率 `knockBackRate_` | — / `1` |
| 目标类型 `target_` | — / `1` |

**移动参数**：等待时间（例 `0.01999999940395355` / `0.01`）

**特效参数**：特效ID（例 `110`）、特效缩放（`1`）、音效名称

> 这与官方组件清单完全对应：`AreaEffectAttackAction`（攻击参数）+ `AreaEffectDelayAction`（延迟）+ `AreaEffectVFXAction`（特效参数）。
> 🔵 **这就是"效果自带段数/范围"的落点** —— 但它是 **FSM 层**，而炎帝的动作挂不上 FSM。

### 4.4 实测用例：用 `Flag1` bit4 加 FSM 调用

参考工具展示的 `pl2900` motion `31a2`（效果：5 发弹）：

```
行 2  触发  0.2500-0.6833  Flag1=16  调用FSM技能
行 3  触发  0.3500-0.6833  Flag1=16  调用FSM技能
行 4  触发  0.4500-0.6833  Flag1=16  调用FSM技能
行 5  触发  0.5500-0.6833  Flag1=16  调用FSM技能
行 7  持续  0.9166-8.3333  Flag1=16  调用FSM技能
```

→ **同一个 motion 里可以加多行 FSM 调用**，每一行在其 `StartTime` 触发一次。
参考工具作者的解释：*"加了 5 个，所以第一次点右键的时候会丢出 5 个"*。

> 🔵 **对本项目的意义**：这证明"一个动作可以多次调用效果"是**flags 轨层面的能力**（加行即可），
> 只是炎帝的 FSM 挂载被 exe 限制住；而 `seq_edit_effect` 轨的"加行"不生效（见 `docs/角色动作探索汇总.md` §8）。

## 5. 「引用此动作编号」—— 动作 ↔ motion 的反向索引

参考工具会列出**哪些技能引用了这个 motion 编号**。例：

| motion | 被哪些动作引用 |
|---|---|
| `pl1800_3100` | △攻击 `#200`、△攻击 精准 `#210`、△攻击 链接攻击从 `#220 → linkattack`、△攻击 能力从 `#230` |
| `pl1800_3106` | 同上 |
| `pl2900_31a2` | 「XXX」`#103`、永暗一闪后连击收招5 `#954 → normalfinish` |

> 这张表的用途：**改一个 motion 会影响所有引用它的动作**。
> 本项目的等价做法：扫全部 `plXXXX_action.msg` 的 `saveMotId01_`~`12_`，反查 motion 号。
